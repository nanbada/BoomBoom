## 현재 결정

시즌 1 출연진은 토비·모모·바나비로 목소리 3개가 필요하다. 대사별로 생성하므로 출연진이 늘어도 파이프라인은 바뀌지 않는다.

| 역할 | 엔진 | 비고 |
|---|---|---|
| 기준 후보 1 | Gemini 3.8 Flash TTS (`gemini-3.8-flash-tts`) | Voice Design으로 캐릭터별 `voice_...` ID 생성 |
| 기준 후보 2 | Fish Drama 3 (`model: drama-3` 헤더) | 연기 품질이 분명히 앞서면 메인 |
| 차선 | ElevenLabs Starter | 기준 후보 둘 다 탈락하거나 약관 문제가 생길 때. 글자 단위 타임스탬프 제공 |
| 로컬 대안 | Qwen3-TTS (VoiceDesign → Base 클론) | Apache-2.0. Mac 실행 여부 미확인 |

파일럿에서 두 기준 후보의 차이가 작으면 Gemini를 메인으로 정한다. 커스텀 보이스를 저장해 두고 대사마다 불러 쓰는 구조가 가장 단순하기 때문이다. Fish가 감정 연기나 음색에서 분명히 앞서면 Fish를 고른다. 어느 쪽이든 월 TTS 비용이 몇 달러 수준이라 비용은 선정 기준에서 뺀다. 다만 Gemini 가격은 2027-01-01부터 두 배가 되고, Fish는 11/12 할인이 끝나면 공지된 정가(100만 자당 $50)가 된다. 월 3만 자 기준 차이는 $1.20이라 할인 종료는 일정 근거로 삼지 않는다. 1단계에서 실제 사용량으로 다시 계산한다.

ElevenLabs를 제외하지 않고 차선으로 둔 이유가 있다. 초안의 제외 근거 중 Voice Library 공유 금지는 계획이 처음부터 공유하지 않기로 해서 영향이 없다. "18세 미만 대상 서비스는 사전 승인 필요"라는 조항은 공식 정책에서 찾지 못했다. 같은 성격의 조항은 오히려 Gemini API 약관에서 확인됐다(아래 '파일럿 전 확인').

### 넣지 않는 선택지

- Dia2: CUDA 전용이고 화자가 2명으로 제한된다. 생성할 때마다 음색이 달라진다.
- RVC(Applio), IndexTTS-2.5, Chatterbox: 처음에는 넣지 않는다. 특정 문제가 생기면 그때 검토한다.
- 가이드 녹음 → Speech-to-Speech: 시즌 1에서는 쓰지 않는다. ElevenLabs로 넘어가더라도 TTS만 쓴다.

## 제작 파이프라인

```
Voice Design (토비·모모·바나비: voice_id + 기준 WAV)
  → script.yaml에서 대사 목록 추출 (대사ID · 캐릭터ID · 텍스트 · 감정 · 장면ID)
  → TTS 어댑터 (Gemini / Fish) — 발화 턴 단위로 단일 화자 생성
  → WAV 저장 + 음성 검수 (발음 · 음색 일관성 · 감정 · 채택 테이크 기록)
  → 강제 정렬 (로컬, 대사 원문 기준 → 단어 타이밍)
  → Rhubarb Lip Sync (캐릭터별 WAV + 대사 원문 → 입모양 타임스탬프)
  → Remotion 조립·렌더 (입모양 · 표정 · 컷 길이 · 자막 팝업)
  → ffmpeg 믹싱·loudnorm
```

대본의 원본은 `script.yaml` 하나다. 대사 목록은 여기서 뽑아 만들고 손으로 따로 고치지 않는다. 대사 문자열은 셸 명령에 넣지 않고 API 요청 본문으로만 보낸다.

Gemini TTS는 단어·글자 타임스탬프를 주지 않는다. Fish Drama 3가 타임스탬프를 지원하는지는 확인하지 못했다. 자막 팝업과 목표 단어 강조에는 단어 타이밍이 필요하므로, 엔진과 상관없이 로컬 강제 정렬 단계를 둔다. 도구는 1단계에서 무료·로컬 후보(Montreal Forced Aligner, WhisperX 등)의 최신 문서를 확인하고 고른다.

정렬기와 Rhubarb는 경계를 따로 추정하므로, 같은 WAV를 쓴다고 저절로 맞지는 않는다. 타이밍은 이렇게 맞춘다.

- 앞뒤 무음을 잘라 낸 최종 채택 WAV 하나를 정렬기와 Rhubarb의 공통 입력으로 고정한다. WAV를 다시 자르면 둘 다 다시 돌린다.
- 대사마다 장면 안 시작 시점(오프셋)을 정하고, 단어 구간과 입모양 구간에 같은 오프셋을 더해 한 타임라인에 놓는다. 프레임 변환은 한 곳에서만 한다.
- 감정·발화 태그(`<laugh>` 등)는 TTS 입력에만 쓰고, 정렬용 텍스트와 화면 자막에서는 뺀다. 웃음·숨소리 구간은 입모양만 쓰고 자막을 띄우지 않는다.
- 목표 단어 팝업은 귀로 들은 시작 시점과 2프레임(30fps 기준) 안에 맞춘다. 벗어나면 그 단어만 손으로 보정하고 보정 사실을 남긴다.
- 챈트 대사는 한 줄씩 생성해 120 BPM 박자 칸에 먼저 배치한 뒤, 배치가 끝난 WAV로 정렬한다.

대사별 생성은 기술적으로 꼭 필요한 방식은 아니다. 수정과 립싱크 자동화가 쉬워서 택했다. 한 줄에 발음 오류가 나면 그 파일만 다시 만든다. 운영 규칙은 다음과 같다.

- 생성 단위는 자연스러운 발화 턴 하나다. 단어 단위로 쪼개지 않는다.
- 대사 사이 간격은 편집 단계에서 장면과 반응에 맞춰 다르게 준다. 간격이 일정하면 기계적으로 들린다.
- 겹치는 발화(Gemini `|reaction|`)는 쓰지 않는다. 맞장구와 웃음도 별도 대사로 생성한다.
- 음성을 먼저 확정하고, 그 길이에 맞춰 애니메이션을 만든다. 발화 길이를 강제하는 TTS는 쓰지 않는다.
- TTS 추상화 프레임워크는 만들지 않는다. 대사 목록을 공통 입력으로 두고 엔진별 어댑터 2개만 만든다. ElevenLabs로 넘어가면 그때 어댑터를 추가한다.
- 효과음은 파일럿에 필요한 최소 세트만 먼저 CC0 또는 직접 합성으로 확보하고, 출처·라이선스를 `05_Ops/assets_log.csv`에 적는다. 목표 단어 앞에서는 효과음이 잦아든 뒤 말이 나오게 하고, 대사 구간에서는 BGM을 낮춘다.

## 캐스팅 원칙

- 목소리 나이는 파일럿에서 정한다. 같은 캐릭터를 아이 음색과 어려 보이는 성인 음색 두 가지로 설계해 비교한다. 성인 음색 쪽이 합성 품질이 안정적이고 발음이 또렷하다는 것이 초안의 가설이다. 어느 쪽이든 실존 아동의 목소리는 녹음·복제·모방하지 않는다.
- 악센트는 세 캐릭터 모두 표준 미국식 영어로 맞춘다.
- 캐릭터는 피치를 올려 구분하지 않는다. 음색, 속도, 에너지로 구분한다.
- 성격 대비를 분명히 한다. 토비는 리더, 모모는 사고뭉치(계획 §4), 바나비는 조연으로 둘과 겹치지 않는 음색을 쓴다.
- Voice Design 프롬프트에는 고정 특성(나이대, 음색, 억양, 기본 말투)만 1~2문장으로 쓴다. 기존 작품이나 캐릭터 이름은 넣지 않는다.
- 대사별 `style`에는 감정 변화만 짧게 쓴다. 긴 Audio Profile 문단은 음색을 흔드는 주된 원인이다.

## 보이스 자산 관리

```
02_Assets/voices/            # 전체 git 제외, 계획 §7 백업 대상
├── toby/
│   ├── master_reference.wav  # Gemini sample_audio 등
│   └── sample_dialogues.wav

└── barnaby/ (동일)
```

보이스 정보의 원본은 `05_Ops/voices.md` 하나다. 캐릭터별로 voice ID, 엔진, 모델, 설계 프롬프트, 생성일, 마지막 사용일, 상업 이용 근거(약관 URL과 확인일)를 적는다. 파이프라인은 voice ID를 이 파일에서 읽거나 `.env` 밖의 설정 파일 하나로 옮겨 쓰되, 두 곳에 따로 적지 않는다.

에피소드마다 채택한 테이크는 대사ID와 함께 `04_Episodes/EPxx_<slug>/` 안의 기록 파일에 남긴다. 기록에는 엔진, 모델, voice ID, 요청 텍스트·style, 생성일, 정렬 결과 파일 이름을 넣는다. 생성 음성은 `05_Ops/assets_log.csv`에 도구·플랜·모델·생성일·라이선스와 함께 기록한다.

백업은 계획 §7대로 서로 다른 두 곳에 둔다. 3단계에서 한 번, 백업만으로 EP01 음성 트랙을 다시 조립하는 복원 시험을 한다.

Gemini 저장 보이스의 조건은 이렇다.

- 프로젝트당 200개까지 저장된다(설계 보이스와 복제 보이스 합산).
- 마지막 사용 후 1년간 쓰지 않으면 삭제된다. 합성에 쓸 때마다 기간이 다시 시작된다.
- 문서에 보이스 내보내기 기능이 없다. `GetVoice`가 만료일을 돌려주는지는 확인하지 못했으므로, `voices.md`에 마지막 사용일을 직접 기록하고 6개월 넘게 쓰지 않은 보이스는 한 번 합성해 기간을 갱신한다.

기준 WAV는 음색 비교와 재현 시험용 자료이고, 백업 모델로 쓸 수 없다. Gemini Voice Replication은 실제 화자의 동의 녹음을 요구하므로 합성 WAV를 다시 등록하는 용도로는 쓸 수 없다. Qwen3나 Fish에서 같은 음색이 나오는지는 직접 시험해야 한다.

캐릭터 음성을 확정한 뒤에는 엔진을 임의로 바꾸지 않는다. 서비스 중단이나 약관 변경으로 엔진을 바꿔야 하면 원장님 승인을 받아 다시 캐스팅하고, 공개 전 비축분만 다시 생성한다. 공개된 편은 그대로 둔다.

## 엔진별 확인 결과 (2026-10-21, 공식 문서 기준)

Gemini 3.8 Flash TTS

- 2026-09-22 정식 출시(GA)됐다(Gemini API changelog).
- 가격(Standard): 입력 텍스트 100만 토큰당 $0.50, 출력 오디오 100만 토큰당 $9.00(2026-12-31까지). 2027-01-01부터 각각 $1.00, $18.00.
- 무료 티어가 있지만 입력과 출력이 Google 제품 개선에 쓰이고 사람이 검토할 수 있다. 공개 전 대본을 다루므로 유료 티어만 쓴다.
- 멀티스피커 단일 요청은 프리셋 보이스 2명까지만 된다. 커스텀 보이스는 턴별로 따로 생성한다.
- 단일 요청 출력은 24kHz mono 16-bit WAV다.
- 단어·글자 타임스탬프를 주지 않는다.
- Voice Design 문서는 아이 음색 설명의 허용 여부를 다루지 않는다.

Fish Drama 3

- 프리뷰다. `POST /v1/tts`에 `model: drama-3` 헤더를 붙이고 본문에 `reference_id`를 넣는다. `POST /model` 등록이 Drama 3에 그대로 쓰이는지는 API 레퍼런스에서 다시 확인한다.
- 10/13~11/12 API 가격은 100만 자당 $10이고, 공지 문구는 정가 $50에서 80%를 할인한 가격이다.
- 테이크마다 결과가 달라서 여러 번 렌더링해 고른다.
- 단어 단위 인페인팅과 인터랙티브 편집은 일반 API에서 쓸 수 없다. 비교 장점으로 세지 않는다.
- 유료 서비스 이용자는 상업적으로 쓸 수 있다(약관). 종량제 API가 유료 서비스에 해당한다는 명시 문구는 아직 찾지 못했다.
- 약관상 이용자가 올린 콘텐츠와 사용 데이터를 Fish의 AI 모델 학습에 쓸 수 있고, 약관 본문에는 거부 방법이 없다. 보이스를 비공개로 두는 것과 학습 제외는 별개다.
- 오픈 웨이트는 연 매출 50만 달러 미만일 때 상업 이용이 무료다(Fish Audio Community License). 필요한 GPU 사양은 공식 자료에서 확인하지 못했다. 공개된 벤치마크는 H200 기준이다.

ElevenLabs (차선)

- Starter는 월 $6, 30,000크레딧, 상업 라이선스를 포함한다. 무료 플랜과 베타 기능 산출물은 상업적으로 쓸 수 없다.
- `convert-with-timestamps`가 글자 단위 타이밍을 준다.
- 아이 음색이나 아이처럼 들리는 성인 음색은 Voice Library에 올릴 수 없다. 내 계정 안에서 쓰는 것을 금지하는 조항은 찾지 못했다.

Qwen3-TTS

- Apache-2.0 라이선스다. README가 VoiceDesign으로 기준 클립을 만들고 Base 모델로 클론하는 흐름을 소개한다.
- README 예제는 CUDA와 FlashAttention 2 기준이다. Apple Silicon 실행은 1단계에서 직접 시험하고, 안 되면 로컬 대안에서 뺀다.

## 엔진 사용 전 확인

아래 항목은 각 엔진에 처음 API를 호출하기 전(Voice Design, TTS, 모델 등록 모두 포함)에 끝낸다. 파일럿 대본과 캐릭터 음성도 이 확인이 끝난 엔진에만 보낸다. 풀리지 않은 엔진은 파일럿에서도 뺀다.

1. Gemini API 약관의 연령 조항. 원문은 18세 미만을 대상으로 하거나 18세 미만이 이용할 가능성이 높은 앱·서비스에서는 이 API를 쓸 수 없다는 내용이다. 성인이 오프라인에서 생성해 아동용 영상에 넣는 경우가 여기에 해당하는지 문구만으로는 알 수 없다. 원문 전체와 Prohibited Use Policy를 읽고, 그래도 불분명하면 Google에 문의해 서면 답을 받는다. 유료 티어나 성인 음색을 쓴다고 이 문제가 풀리지는 않는다.
2. Fish 약관에서 종량제 API 산출물의 상업 이용 근거, 아동 대상 콘텐츠 제한 여부, 합성 WAV를 `POST /model`에 등록할 때 동의 절차가 적용되는지.
3. Fish의 학습 이용 조항. 개인정보처리방침에 거부·보존·삭제 방법이 있는지 확인하고, 공개 전 대본과 캐릭터 음성이 학습에 쓰여도 되는지 원장님이 정한다. 학생 관련 자료는 어떤 경우에도 올리지 않는다.
4. 두 서비스에 사용량 한도(예산 알림)를 걸고 API 키는 `.env`에만 둔다.

## 파일럿 계획 (1단계, 11/9까지)

동일한 60~90초 대본으로 비교한다. 대본에는 토비·모모·바나비가 모두 나오고 일반 대화, 빠른 주고받기, 감정 변화, 영어 학습용 발음 장면, 챈트 두 줄을 넣는다. 토비와 모모는 엔진마다 아이 음색과 성인 음색을 하나씩, 바나비는 한 가지로 설계한다. 장기 일관성은 같은 voice ID로 다른 날 한 번 더 생성해 비교한다.

1단계 종료 조건은 메인 엔진, 목소리 나이, 정렬 도구, 세 캐릭터의 voice ID가 정해진 상태다. Qwen3 Mac 시험과 Fish 2인 통합 생성 비교는 시간이 남을 때만 하고, 못 하면 2단계 이후로 미룬다.

| 평가 기준 | 비중 |
|---|---|
| 캐릭터 음색의 고유성·일관성 | 30% |
| 영어 발음의 명료성·정확성 | 25% |
| 감정 연기의 자연스러움 | 20% |
| 대화 흐름의 자연스러움 | 15% |
| 재생성·편집 편의성(정렬 결과 포함) | 10% |

초기 품질 목표는 이 프로젝트가 정한 자체 목표다.

- 핵심 단어 누락 0건, 화자 혼동 0건.
- 독립 청취자의 캐릭터 식별 정확도 90% 이상. 청취자는 성인으로 하고, 학생 시청 테스트(계획 §12)와 섞지 않는다.
- 파닉스 핵심 단어는 ASR의 WER와 별도로 직접 듣고 검수한다.
- 강제 정렬로 얻은 목표 단어 시작 시점이 귀로 들은 시점과 거슬리게 어긋나지 않는다.

## 미확인 사항

- Gemini Voice Design이 아이 음색 설명을 받아들이는지
- Gemini 연령 조항과 Fish 약관의 적용 범위, Fish 학습 이용 거부 가능 여부(위 '엔진 사용 전 확인')
- Fish Drama 3의 타임스탬프 지원 여부
- Gemini 기준 WAV로 Qwen3 클론을 만들 때 음색 재현도, Qwen3의 Mac 실행 여부

## YouTube 정책 메모

AI 음성을 쓴다고 수익화가 막히지는 않는다. 걸리는 것은 inauthentic content 정책이다. 줄거리를 템플릿처럼 찍어내거나, 캐릭터를 같은 상황에 반복해 두거나, 대량 생산 인상을 주는 콘텐츠는 수익화에서 빠진다. 아동용 채널은 심사가 더 엄격하다. 에피소드마다 학습 목표와 이야기를 확실히 다르게 설계한다(계획 §5의 `episode_card.md`).
