## 범위

포함:

1. `03_Pipeline/`에 Remotion(React + TypeScript) 프로젝트.
2. `script.yaml` 스키마와 검증기, 대사 목록 추출.
3. 테스트용 음성 생성 스크립트(ElevenLabs 무료 플랜, 아래 조건).
4. Rhubarb Lip Sync 연동(기본 입모양 A~F 6종).
5. 단어 타이밍 → 목표 단어 자막 팝업.
6. 같은 장면 데이터로 16:9(1920×1080)와 9:16(1080×1920) 렌더. 카메라와 자막 배치를 화면비마다 따로 정의하고, 한쪽을 잘라 다른 쪽을 만들지 않는다.
7. ffmpeg 2-pass loudnorm으로 -14 LUFS / -1 dBTP 마스터링.
8. 토비 임시 SVG 리그 후보 5종과 1번 채택.

제외(손대지 않음):

- 로컬 강제 정렬기 선정과 연동. 이번에는 ElevenLabs가 주는 글자 타임스탬프로 단어 타이밍을 만든다. 정렬기가 나중에 같은 `timing.json` 형식을 내도록 인터페이스만 맞춰 둔다.
- Gemini·Fish TTS 어댑터와 그 API 호출. 약관 확인 전이다.
- 배경·소품 이미지 생성(`$imagegen`). 이번에는 단색 배경과 도형 소품 플레이스홀더를 쓰고, 나중에 `02_Assets/`의 실제 자산으로 교체한다.
- 효과음·BGM·챈트, 업로드, 다른 캐릭터.

## 테스트 에피소드

폴더: `04_Episodes/EP00_pipeline_test/`. 내용은 Claude가 정한 아래 데이터를 그대로 쓰고, 문장을 바꾸지 않는다. YAML 형식은 네가 만든 스키마를 따른다.

| 항목 | 값 |
|---|---|
| 길이 | 15초, 30fps |
| 세트 | 단색 배경 플레이스홀더(`bg_placeholder`) |
| 소품 | 커다란 빨간 풍선 플레이스홀더(원 + 끈). 두 번째 대사 직후 작아진다 |

목표 단어 팝업은 귀로 들은 시작 시점과 2프레임 안에 맞아야 한다. 벗어나면 그 단어만 `script.yaml`에서 수동 보정할 수 있게 하고, 보정했다는 사실이 파일에 남게 한다.

## 설계 요구

`script.yaml` 처리

- 안전한 YAML 파서(사용자 정의 태그 없음)로 읽고 스키마(zod 또는 JSON Schema 중 택1)로 검증한다. 잘못된 파일은 줄·필드를 짚는 오류로 실패해야 한다.
- 최소 필드: 에피소드 ID, fps, 길이, 장면 목록(장면ID, 배경ID, 소품, 카메라 16:9·9:16 각각), 대사 목록(대사ID, 캐릭터ID, 텍스트, 감정, 장면ID, 시작 오프셋, 목표 단어, 수동 타이밍 보정).
- 대사 목록(`lines.json`)은 `script.yaml`에서만 생성한다. 감정·발화 태그는 TTS 입력에만 쓰고 자막·Rhubarb 대사 텍스트에서는 뺀다.
- 대본 문자열은 셸 명령이나 `eval`에 넣지 않는다. ffmpeg·Rhubarb는 `execFile`/`spawn` 인자 배열로 실행한다.

음성(테스트 전용)

- ElevenLabs 무료 플랜 API의 `convert-with-timestamps`로 대사별 1파일을 만든다. 키는 `.env`의 `ELEVENLABS_API_KEY`에서 읽는다. `.env.example`을 추가한다.
- 기본 제공(premade) 성인 보이스 하나를 쓴다. Voice Design, 보이스 클론, 아이 음색 설계는 하지 않는다.
- 시작 전에 ElevenLabs 공식 요금·약관 페이지에서 무료 플랜의 API 사용 가능 여부와 크레딧을 확인해 보고서에 URL·확인일과 함께 적는다. 무료 플랜 산출물은 상업 이용이 안 되므로 테스트에만 쓰고, `05_Ops/voices.md`와 `assets_log.csv`에 "테스트 전용, 공개 영상 사용 금지"로 기록한다.
- 결제가 필요하거나 무료 크레딧이 모자라면 멈추고 보고한다. 유료 전환은 하지 않는다.
- 대사별로 캐시한다. 텍스트·보이스·설정이 같으면 다시 호출하지 않고, 바뀐 대사만 다시 만든다.
- 음성 파일은 `04_Episodes/EP00_pipeline_test/audio/`(git 제외)에 WAV로 둔다.

타이밍과 립싱크

- 앞뒤 무음을 자른 최종 WAV 하나를 Rhubarb와 타이밍의 공통 입력으로 쓴다. 잘라 낸 길이만큼 타임스탬프를 옮긴다.
- 글자 타임스탬프 → 단어 타이밍으로 바꿔 `timing.json`(대사ID, 단어, 시작·끝 초)으로 저장한다.
- Rhubarb는 대사 원문을 `--dialogFile`로 주고 JSON으로 출력한다. 확장 입모양은 끈다.
- 대사 오프셋을 단어 구간과 입모양 구간에 똑같이 더하고, 초 → 프레임 변환은 한 함수에서만 한다.

토비 임시 리그

- SVG 코드로 후보 5종을 그려 `02_Assets/characters/toby/_candidates/toby_cand01.svg`~`05.svg`에 두고, 다섯 개를 나란히 놓은 미리보기 PNG를 하나 만든다. 1번을 `02_Assets/characters/toby/toby_temp_rig.svg`로 복사해 파이프라인에 쓴다. 원장님 선택을 기다리지 않는다.
- 외형 조건(계획 §4): 골든리트리버, 리더 성격, 2.5~3등신, 검은 실루엣만으로 구분되는 형태, 3색, 입 주변 흰색. 기존 작품·캐릭터를 참고하거나 닮게 하지 않는다.
- 레이어는 `<g id>`로 나눈다: `head`, `body`, `arm_l`, `arm_r`, `leg_l`, `leg_r`, `eyes_open`, `eyes_closed`, `mouth_A`~`mouth_F`. 겹쳐 가려지는 부위도 끝까지 그린다. 팔·머리 회전 기준점을 정해 둔다.
- 임시 리그다. 최종 캐릭터는 원장님이 직접 그린다. 파일 상단 주석과 `assets_log.csv`에 "임시, 공개 영상 사용 금지"를 적는다.
- 움직임은 눈 깜빡임, 입모양, 머리·팔 약간의 회전 정도로 둔다. 번쩍임은 초당 3회를 넘지 않고, 화면 흔들림은 쓰지 않는다.

렌더와 마스터링

- Remotion 컴포지션 두 개(16:9, 9:16)가 같은 장면 데이터를 읽는다. 9:16에서도 토비, 풍선, 자막이 잘리지 않아야 한다.
- 렌더 결과는 `03_Pipeline/out/`(git 제외). loudnorm 측정값(통합 음량, 트루 피크)을 보고서에 붙인다.
- 명령 하나로 전체를 돈다. 예: `npm run build:episode -- ../04_Episodes/EP00_pipeline_test`. 검증 → 대사 추출 → 음성(캐시) → 타이밍 → Rhubarb → 렌더 2종 → loudnorm.

환경

- 원장님 Mac(Apple Silicon)에서 돈다. Node, ffmpeg, Rhubarb 설치 여부와 버전을 먼저 확인해 보고서에 적는다. 없는 도구는 설치 방법을 보고서에 적고, Homebrew로 한 줄에 설치되는 것만 설치한다.
- Remotion을 포함한 라이브러리 버전은 npm 레지스트리와 공식 문서에서 현재 값을 확인하고 고정한다. Rhubarb는 GitHub 공식 릴리스만 쓴다.
- 요청하지 않은 기능, 설정 옵션, 추상화 계층은 만들지 않는다. TTS 엔진 추상화 프레임워크도 만들지 않는다.
