## 할 일

1. 장면 결과를 데이터로 옮긴다. `video/Episode.tsx:53`의 `id === 'L02'` 고정(풍선 축소·만족 표정)과 `scripts/build-episode.ts:79`의 `secondsToFrames(12, …)` 고정을 없앤다. 풍선 축소와 표정 변화를 일으키는 대사 ID는 `script.yaml`에서 읽고, 종료 정지 확인 프레임은 에피소드 데이터(대사 종료·길이)에서 계산한다. 스키마에 필드를 추가하면 존재하지 않는 대사 ID를 참조할 때 실패하게 하고 테스트를 단다. 필드는 최소로 한다. EP00 결과 화면은 바뀌지 않아야 한다.
2. 테스트 공백을 메운다. 네트워크 없이: `generateTake`의 캐시 적중(API 미호출)과 누락(1회 호출, 모의 fetch), 립싱크 입모양 구간에 단어 타이밍과 같은 오프셋(무음 제거·startOffset)이 적용되는지.
3. API 무호출 재빌드. 재빌드 전에 현재 `out/EP00/EP00_16x9.mp4`, `EP00_9x16.mp4`를 `out/EP00/prev/`에 복사한다. `npm run build:episode -- ../04_Episodes/EP00_pipeline_test`를 돌려 두 대사 모두 cacheHit=true임을 확인한다. 캐시 누락이 하나라도 나면 TTS를 부르지 말고 멈춰 보고한다. 재빌드 뒤 이전 영상과 비디오 프레임이 같은지(ffmpeg `framemd5` 등) 비교하고, 음량을 재측정한다.
4. 발화 시작 실측(완료 조건 4). 최종 대사 WAV에서 `big`, `small`의 실제 발화 시작을 신호로 측정한다(예: 단어 타임스탬프 주변의 에너지·스펙트럼 onset). 방법, 측정값(초·프레임), 팝업 첫 프레임(83·163)과의 차이를 보고서에 적는다. 자동 측정값이라는 점과 한계를 밝히고, 사람의 프레임 단위 확인을 대체한다고 주장하지 않는다. 차이가 2프레임을 넘으면 그 단어만 `timingCorrections`로 보정하고 3번 재빌드를 다시 한다.
5. 보고서에 "Claude 교차 검토와 후속 조치" 절을 추가한다. 위 검토 결과, 이번 변경 파일, 테스트 수, 재빌드 시간·cacheHit, 프레임 비교 결과, 음량, 4번 측정 결과, 남은 일(세로 영상 사람 시청, 두 위치 백업, push·병합은 원장님 결정)을 적는다.
